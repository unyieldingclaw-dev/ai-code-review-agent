# v0.9.0 Design: Live Progress + Fail-Fast Early Exit

**Date**: 2026-06-15
**Status**: Approved
**Version target**: 0.9.0

---

## Context

After v0.8.0 shipped 5 new specialist agents (16 total), a full swarm run takes 20–32 minutes sequentially with no feedback during that window. The two changes in this version make the wait bearable:

1. **Live progress output** — per-agent status lines written to stderr as the swarm runs
2. **`--fail-fast` early exit** — optional flag that stops the swarm as soon as a finding meets the configured `failOn` severity threshold, then returns partial results

A calibration quality pass for the 5 new agents (ErrorHandling, Observability, MigrationSafety, Secrets, Complexity) follows as v0.9.1 — prompt iteration using the existing `calibrate.ts` runner, no code changes.

---

## New Type: `AgentProgressEvent`

File: `src/core/schema.ts`

```typescript
export interface AgentProgressEvent {
  phase: 'start' | 'end'
  name: AgentName
  index: number // 1-based position in the run order
  total: number // total agents scheduled to run this session
  findings?: Finding[] // populated on 'end'
  elapsedMs?: number // populated on 'end'
  earlyExit?: boolean // 'end' only — true if swarm stops after this agent
}
```

`total` reflects actual agents scheduled after config filtering (includes CoverageAnalyst and TestGen if enabled).

## SwarmRunner Changes

File: `src/core/runner.ts`

**Callback signature** — change from:

```typescript
onProgress?: (name: string) => void
```

to:

```typescript
onProgress?: (event: AgentProgressEvent) => void
```

**Per-agent loop additions:**

- Fire `{ phase: 'start', name, index, total }` before each agent
- Record `startTime = Date.now()` before agent call
- Fire `{ phase: 'end', name, index, total, findings, elapsedMs }` after agent completes
- After the 'end' event, evaluate early-exit:

```typescript
const severityRank: Record<Severity, number> = { critical: 3, high: 2, medium: 1, low: 0 }
const shouldStop =
  (config.failFast ?? false) &&
  allFindings.some((f) => severityRank[f.severity] >= severityRank[config.failOn ?? 'high'])
if (shouldStop) {
  earlyExitAgent = name
  break
}
```

- If `earlyExitAgent` is set, skip TestGen (checked before the TestGen block)
- Set `result.earlyExit = { stoppedAt: earlyExitAgent }` on the returned result

## CLI Changes

File: `src/cli/index.ts`

**New flag:**

```
--fail-fast    Stop the swarm as soon as a finding meets the --fail-on threshold
```

**Progress renderer** (writes to stderr, no stdout pollution):

- `phase: 'start'`:
  ```
  [3/16] SecurityAgent  starting…
  ```
- `phase: 'end'` (compact, omits zero-count severities):
  ```
  [3/16] SecurityAgent  47s — 2 findings (1 critical, 1 high)
  ```
- `phase: 'end'` with `earlyExit: true`:
  ```
  [3/16] SecurityAgent  47s — 2 findings (1 critical, 1 high)
  ⚡ Fail-fast: stopping swarm after SecurityAgent (critical threshold met)
  ```

**Report footer** — if `result.earlyExit` is set, append to the markdown output:

```markdown
> ⚡ **Review stopped early** — fail-fast triggered after `SecurityAgent`.
> Remaining agents were not run. Re-run without `--fail-fast` for a complete review.
```

## Tests

All mockable — no Ollama required.

1. `onProgress fires 'start' before 'end' for each agent`
2. `onProgress 'end' includes findings and elapsedMs`
3. `failFast: true stops swarm after Critical finding; remaining agents not called`
4. `failFast: true does not stop when all findings are below failOn threshold`
5. `failFast: false (default) runs all agents regardless of finding severity`

## Rejected Alternatives

- **Spinner library (`ora`)** — external dep for cosmetic benefit; plain `process.stderr.write` is sufficient
- **`--stream` mode printing findings to stdout** — duplicates findings (once streaming, once in final report); using stderr for all progress avoids this
- **Separate `failFastOn` config knob** — reusing `failOn` keeps the mental model simple; `--fail-fast` means "stop early when you'd fail anyway"
