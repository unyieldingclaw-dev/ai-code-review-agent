# ACR Full-System Integrity & Hardening Review — Final Report

## Executive Summary

ACR's core architecture is sound: no command injection anywhere in the codebase (verified — every `spawn` call site uses an argument array, never string interpolation), path-containment defenses for both the MCP `repo_path` allowlist and the `--write-tests` write path are genuinely robust (empirically probed against traversal, UNC paths, alternate data streams, and drive-relative payloads on real Windows Node), SSRF via a malicious `ollamaUrl` is specifically blocked by a hostname allowlist, the dependency surface is minimal and lockfile-pinned, and the codebase has essentially zero dead code or orphaned files.

Set against that, the audit surfaced one dominant, cross-cutting defect class: **`severity`, `basis`, `blocking`, and `source` — the four fields that drive every downstream trust, filtering, and exit-code decision — are never validated against their enums anywhere in the pipeline.** This single gap silently corrupts CI exit-code gating, the hallucination-corroboration safety net, sort ordering, and the publication filter, in at least 8 independent call sites across 4 files. Three specific agents' own prompts make the trust-bypass instance of this concretely exploitable by instructing the LLM to self-tag a `source` value that no real tool ever backs. All three files where these bugs live show 95–100% test coverage — the bugs are invisible to coverage by construction, because they are _absences_ of validation, not unexercised branches.

The second major theme is a **failure-visibility gap on the MCP path** specifically: `src/mcp/formatter.ts` never reads `agentStatus` or `truncation`, so a run where every agent times out and the diff was truncated to 16% of its size renders as an identical, confident "✅ No findings" to the calling LLM — the one consumer least able to notice, and the exact path `/change-review` Job 7 uses for real gating decisions. SARIF has the equivalent gap for CI consumers.

The third theme is **governance-layer bypass surface**: the local hooks that gate commits/pushes and scan for secrets are wired to specific tool matchers (not all of them), use literal-substring git-command detection (evaded by `git -c core.hooksPath=...`, aliases, or `git.exe`), bind their authorization markers to diff content rather than actor identity (a cross-session TOCTOU), and have no server-side backstop — a secret pushed via a bypass path reaches GitHub with zero automated check catching it until, if ever, a release tag is cut.

Every headline claim below was independently confirmed by reading the actual source (12 phases, ~30 file-reading passes) and 7 of the highest-severity claims were additionally reproduced empirically — real code, real malformed input, real output — in Phase 13, with 7/7 reproducing exactly as predicted.

## Efficiency Findings (Phase 10 summary)

**Already well-optimized:** evidence-verifier prompt scoping (claim+evidence only, never the full diff); within-run semantic-context caching across agents/retries; `migration-safety`'s deterministic whole-agent skip; timeout scaling (pure wall-clock, doesn't add LLM cost).

**Real waste, ranked by impact:**

1. M17 — `license` agent: 0% code-level skip rate, always burns a call
2. M18 — `dependencies` agent: skip guard fires in ~0% of real-world repos (any repo with a `package.json` on disk defeats it)
3. M19 — chunking: flat N× multiplier, up to ~8x combined with default retries for a 4-chunk diff
4. M20 — semantic-context memory-bank re-embedding per chunk (identical content, recomputed N times)
5. Retry cost (`retryAttempts: 2` default) — invisible in output, no aggregate cost accounting anywhere in `ReviewResult`
6. `runEvidenceChecks` — no batching, one call per eligible finding, always against a separately-loaded `verifierModel` (model-swap cost on every `--verify-evidence` run)

## Architecture Findings (Phase 11 + agent-overlap findings from Phase 4)

## Test Gaps (Phase 7 summary — the headline finding)

The test suite is large (550+ tests, ~8,000 lines) and assertion quality is genuinely good where sampled (strong `toBe`/`toEqual`/`toContain` assertions dominate; weak assertions are rare and never load-bearing alone). But:

- **H10**: 95–100% coverage on the exact files containing the audit's top bugs — coverage cannot detect an absence-of-validation defect, only whether existing lines executed.
- **H2**: one bug (`blocking` default) isn't just untested — an existing test explicitly asserts the buggy behavior as correct.
- Every agent-test mock (`makeProvider(response)` pattern, ~35 files) feeds only well-formed enum values. No test anywhere feeds a garbage `severity`/`basis` string, which is exactly the shape of input that triggers C2.
- 5 traced "if this wire were cut, would a test fail?" scenarios: 2 of 5 (CLI exit-code gating, `DETERMINISTIC_SOURCES` skip for genuinely-deterministic sources) are covered; 3 of 5 (MCP `agentStatus` forwarding, `capAndSort` enum-safety, `--agents`/`--fail-on` invalid-input handling) have **zero** test coverage on either side of the wire.
- `orchestratorAgent.test.ts` is confirmed redundant — a real, if minor, maintenance-burden finding.
